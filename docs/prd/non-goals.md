# Non-Goals：明确不做与延期清单

- 工单：SC-0101
- 状态：已定稿（2026-11-03，与 PRD §7.4 同轮定稿）
- 用途：与 `docs/prd/README.md` 配套，回答“这个项目不做什么”；砍需求、收到新想法时先查这里。
- 原则：进度落后时先砍 Should/Could，绝不砍 Must、测试、鉴权、库存正确性（对齐 ADR-0001）。

## 1. 永久不做（项目级红线）

| 项 | 原因 |
|---|---|
| 真实收款/支付渠道接入 | 学习项目，只做模拟支付回调 |
| 真实物流/退货履约 | 同上，售后只是工单流转 |
| 真实退款打款 | 售后 RESOLVED 只是结果标记，不动钱 |
| 真实支付渠道凭据/签名密钥 | 模拟支付只用本地演示签名（`.env` 占位），不接入任何真实渠道密钥 |
| 真实通知渠道（邮件/短信/推送） | 学习项目不接真实外部渠道（与真实收款/物流同级）；项目内"通知"只指站内事件链路（Outbox + 幂等消费者，Must） |
| 真实用户数据导入 | 全程使用虚构演示数据 |
| 微服务拆分、服务网格、千万 QPS | 单体是当前正确选择 |
| 模型训练/微调 | 只做推理与 RAG |
| LLM 直接修改订单/退款/绕过认证 | AI 是不可信依赖的铁律 |
| 订单私有数据进公共向量库 | Qdrant 只存公开售后知识 |

## 2. W16 MVP 不做（延期清单）

| 项 | 优先级 | 去向 |
|---|---|---|
| 地址管理（CRUD/选择/脱敏） | Could | 从故事一移出；手册核心表与 API 无 address；MVP 用虚构演示静态收货信息 |
| 订单过期自动关单 | Could（P2） | 手册 3.3“可后续扩展”；从 Must 移出；W16 未支付订单手动取消或保留 CREATED |
| 优惠券/促销/活动价 | Could | 从故事一移出；实付 = Σ(单价 × 数量)；需要价格引擎时再立项 |
| 限购规则 | Could | 无运营后台支撑；quantity 只做参数上限校验 |
| 购物车选中项→下单便捷转换 | Should | W16 后评估；下单本身多 SKU 已是 Must（PRD 1.7 取舍 1），用户直接提交 items[] 下单 |
| 运营后台完整 UI | Could（W18+） | W16 只保留最小管理端接口 |
| 完整观测栈（Prometheus/Grafana/OTel） | W18 | W16 只留 requestId + 结构化日志 |
| 性能压测优化、灰度策略 | — | 没有测量数据不谈性能 |
| 积分、会员、发票 | Could | 未规划 |

> 注 1：PRD §6 的 Should 项（购物车选中项转换、管理端订单查询、售后撤回、Redis 缓存、DLQ 等）是 **W16 内弹性目标**，不属于本清单"不做"；落后时按 ADR-0001 先砍这些，再动本清单。
> 注 2：W10 Gate“退款申请和库存补偿闭环”的库存补偿 = 未支付取消回补全链路（条件更新、幂等、流水）；退款后的库存回补策略由 SC-1001 规则化评估，MVP 仅退款场景强制不回补（PRD INV-A6），不属于本清单延期项。

## 3. 第二里程碑（W19+，不阻塞 W16）

- RAG 售后 FAQ：回答带引用、无依据拒答/转人工、已撤回政策失效。
- AI 只读订单工具 `getMyOrderStatus(orderId)`。
- AI 客服回复草稿：SUPPORT 审核后才成为正式回复。
- 评测：40 条普通评测 + 20 条攻击样本（手册 5.5）、FakeProvider、超时/降级/token 成本预算。

## 4. W27 前不做

- MCP 试验。
- 复杂 Agent 编排、多模型同时接入。

## 5. 裁决规则

- 新需求出现时：先查本文件与 ADR-0001；两处都不含 → 默认不做，记录到 daily 后再议。
- 任何范围变更必须更新 ADR-0001，并在 `STATUS.md` 和 daily 中记录原因。
