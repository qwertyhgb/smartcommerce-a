# 排期规则：计划日期不是截止日期

## 原则

- `tickets.csv` 的 `planned_date` 是建议顺序，不是 deadline。
- 按周结算项目 10h 预算，不按天考核；可以某天 0h、某天 3h。
- 允许提前：前置依赖已完成、测试通过，就可以领取下一张工单；不要跳过依赖。
- 允许延后：Must 顺延到下周，`status=DEFERRED`，`notes` 写原因和计划周；不得伪造 `actual_done`。
- 每周复盘一次：完成/延期/阻塞；下周重新排。
- 连续两周落后 → 触发 ADR-0001 的砍单清单；砍 Should/Could，不砍 Must、测试、鉴权、库存正确性。
- 硬边界：W16 MVP（2027-02-21）和 2027-02 开始的实习投递。

## 状态操作

| 场景 | status | 必填字段 |
|---|---|---|
| 开始 | `DOING` | `actual_start` |
| 完成 | `DONE` | `actual_done`、`evidence`、`commit` |
| 延期 | `DEFERRED` | `notes`（原因、计划周） |
| 阻塞 | `BLOCKED` | `notes`（原因、下一步） |
| 未开始 | `TODO` | — |

## 提前/延后的边界

- 可以提前：同一阶段或前置任务已完成；不要为了提前跳过依赖。
- 不可以：跳过 Must 测试；把 AI 阶段提前到交易核心稳定之前；用改状态代替证据。
- 计划日期过期不等于失败；只看 `status` + `evidence`。

## 记录节奏

- `daily/` 只在有工作时写；没有工作不需要补假记录。
- 每周日或周一花 15 分钟复盘：本周完成、延期、阻塞，下周计划。
- 复盘后更新 `STATUS.md` 和 `tickets.csv`，再提交。
